# Задание

В этом задании предстоит реализовать обработку коллизий предметов. Столкновение — это слишком абстрактное понятие, которое сводится к более  простой задаче — определению того, что два объекта пересеклись. Часть коллизий ваш сервер уже умеет обрабатывать — столкновение собаки с краем дороги.



## Немного теории, которую нужно будет использовать

Пересечение кругов – расстояние между центрами не более R + r. Функцию определения пересечения можно записать так:

```
struct Circle {
    double x, y;
    double r;
};

bool CheckCirclesForIntersection(Circle c1, Circle c2) {
    // Вычислим расстояние между точками функцией std::hypot
    return std::hypot(c1.x - c2.x, c1.y - c2.y) <= c1.r + c2.r;
} 
```

Чтобы понять, пересекаются ли прямоугольники, достаточно узнать, пересекаются ли их проекции на координатные оси X и Y. Решим эту задачу такой функцией:

```
struct LineSegment {
    // Предполагаем, что x1 <= x2
    double x1, x2;
};

std::optional<LineSegment> Intersect(LineSegment s1, LineSegment s2) {
    double left = std::max(s1.x1, s2.x1);
    double right = std::min(s1.x2, s2.x2);

    if (right < left) {
        return std::nullopt;
    }

    // Здесь использована возможность C++-20 - объявленные 
    // инициализаторы (designated initializers).
    // Узнать о ней подробнее можно на сайте cppreference:
    // https://en.cppreference.com/w/cpp/language/aggregate_initialization#Designated_initializers
    return LineSegment{.x1 = left, .x2 = right};
} 
```

Используем тот факт, что прямоугольники пересекаются, если пересекаются их проекции на оси:

```
// Вычисляем проекции на оси
LineSegment ProjectX(Rect r) {
    return LineSegment{.x1 = r.x, .x2 = r.x + r.w};
}

LineSegment ProjectY(Rect r) {
    return LineSegment{.x1 = r.y, .x2 = r.y + r.h};
}

std::optional<Rect> Intersect(Rect r1, Rect r2) {
    auto px = Intersect(ProjectX(r1), ProjectX(r2));
    auto py = Intersect(ProjectY(r1), ProjectY(r2));

    if (!px || !py) {
        return std::nullopt;
    }

    // Составляем из проекций прямоугольник
    return Rect{.x = px->x1, .y = py->x1, 
                .w = px->x2 - px->x1, .h = py->x2 - py->x1};
} 
```

**Сбор предмета**

Позволить собакам собирать предметы и относить их на базу. Сбор предмета — это столкновение собаки и предмета, а возвращение на базу — столкновение собаки и базы. Пересечение будем искать во время тика. При этом собака могла  переместиться из некоторой точки A в точку B. Будем считать, что собака  имеет ширину 0,6 единиц и при прямолинейном перемещении заметает  некоторый прямоугольник: его ширина равна ширине собаки, а длина —  пройденному пути. Длиной собаки мы пренебрегаем. Она подбирает все  предметы, попавшие внутрь прямоугольника.

В предположении, что собаки могут двигаться только по горизонтали и вертикали, задача решается довольно просто. Но рассмотрим более общий случай — когда вектор скорости произвольный. В этом случае нужно понять, попадает ли проекция точки на отрезок AB, а также найти расстояние от точки до отрезка — только так мы сможем определить попадание точки внутрь белого прямоугольника.

Нам поможет операция скалярного произведения.  За вектор v возьмём вектор перемещения из точки A и точку B, а вектор u — вектор, указывающий из точки A на предмет, который мы хотим подобрать. Код, реализующий эту логику:

```
struct Point {
    double x, y;
};

struct CollectionResult {
    bool IsCollected(double collect_radius) const {
        return proj_ratio >= 0 &&
               proj_ratio <= 1 &&
               sq_distance <= collect_radius * collect_radius;
    }

};

// Движемся из точки a в точку b и пытаемся подобрать точку c.
// Функция корректно работает только при условии ненулевого перемещения.
CollectionResult TryCollectPoint(Point a, Point b, Point c) {
    // Проверим, что перемещение ненулевое.
    // Тут приходится использовать строгое равенство, а не приближённое,
    // поскольку при сборе заказов придётся учитывать перемещение даже на небольшое 
    // расстояние.
    assert(b.x != a.x || b.y != a.y);
    const double u_x = c.x - a.x;
    const double u_y = c.y - a.y;
    const double v_x = b.x - a.x;
    const double v_y = b.y - a.y;
    const double u_dot_v = u_x * v_x + u_y * v_y;
    const double u_len2 = u_x * u_x + u_y * u_y;
    const double v_len2 = v_x * v_x + v_y * v_y;
    const double proj_ratio = u_dot_v / v_len2;
    const double sq_distance = u_len2 - (u_dot_v * u_dot_v) / v_len2;

	return CollectionResult(sq_distance, proj_ratio);

}
```

## Нужно сделать

Чтобы в игре можно было собирать объекты и возвращать их на базу, применим функцию `FindGatherEvents` из пространства имён `collision_detector`. Она принимает два типа объектов — собиратели (Gatherer) и предметы (Item). Эти списки передаются посредством специального объекта (ItemGathererProvider). Результатом будет список событий сбора (GatheringEvent). 

```
std::vector<GatheringEvent> FindGatherEvents(const ItemGathererProvider& provider); 
```

В этом задании писать функцию не нужно. Напишите тесты для неё.

Предмет характеризуется позицией и размером:

```
struct Item {
    geom::Point2D position;
    double width;
}; 
```

Собиратель характеризуется размером и отрезком перемещения:

```
struct Gatherer {
    geom::Point2D start_pos;
    geom::Point2D end_pos;
    double width;
}; 
```

Считается, что собиратель равномерно двигался по прямой из точки `start_pos` до точки `end_pos`, при этом контактируя со всеми предметами, которые пересекаются с заметаемым им прямоугольником.

Чтобы функция `FindGatherEvents` знала о предметах и собирателях, информация о них передаётся через интерфейс `ItemGathererProvider`:

```
class ItemGathererProvider {
protected:
    ~ItemGathererProvider() = default;

public:
    virtual size_t ItemsCount() const = 0;
    virtual Item GetItem(size_t idx) const = 0;

    virtual size_t GatherersCount() const = 0;
    virtual Gatherer GetGatherer(size_t idx) const = 0;
}; 
```

Его цель — предоставить информацию о существующих собирателях и предметах. Объект класса можно заменить парой векторов, но выбрано более универсальное решение. Класс позволяет узнать количество собирателей и предметов (методами `ItemsCount`, `GatherersCount`), затем получить каждый конкретный объект по его индексу.

Чтобы использовать функцию `FindGatherEvents` в игре, нужно сделать класс, реализующий интерфейс `ItemGathererProvider`. Этот интерфейс будет возвращать собак в виде собирателей, а потерянные вещи — в виде предметов.

Чтобы протестировать функцию `FindGatherEvents` , нужно создать тестовый класс, наследующийся от `ItemGathererProvider`, и передать его экземпляр в функцию.

Событие столкновения характеризуется:

- индексом собирателя,
- индексом предмета,
- квадратом расстояния до предмета,
- относительным временем столкновения собирателя с предметом (число от 0 до 1).

Мы используем квадрат расстояния, чтобы избежать ненужного извлечения корней. В итоге событие выглядит так:

```
struct GatheringEvent {
    size_t item_id;
    size_t gatherer_id;
    double sq_distance;
    double time;
}; 
```

Интерфейс функции должен быть таким:

```
std::vector<GatheringEvent> FindGatherEvents(const ItemGathererProvider& provider) 
```

Функция возвращает вектор событий, идущих в хронологическом порядке. Считается, что предметы остаются после столкновений на своём месте — событие добавляется в вектор, даже если другой собиратель уже сталкивался с этим предметом. Порядок одновременно произошедших событий может быть любым.

Столкновение засчитывается при совпадении двух факторов:

- расстояние от предмета до прямой перемещения собирателя не превышает величины w + W, где w — радиус предмета, а W — радиус собирателя,
- проекция предмета на прямую перемещения собирателя попадает на отрезок перемещения.

Если объект не переместился, считайте, что он не совершил столкновений. При этом учитывайте перемещение на любое ненулевое расстояние — погрешностью можно пренебречь.

### Требования

- При проверке совпадения чисел с плавающей точкой используйте абсолютную погрешность 10⁻¹⁰.
- Используйте фреймворк Catch2.
- Тесты должны проходить успешно для правильной реализации функции и фейлиться на неправильных.

Своими тестами проверьте, что:

- функция `FindGatherEvents` детектирует все события столкновений,
- функция `FindGatherEvents` не детектирует лишних событий,
- события идут в хронологическом порядке,
- события имеют правильные данные — время, индексы, расстояние.
